# MarginIQ | Revenue & Profitability Intelligence

**An end-to-end corporate finance, SQL, and business analytics portfolio project.**

MarginIQ is an interactive financial dashboard built with **Python, Pandas, SQLite, Plotly, and Streamlit**. It helps an analyst explore realized sales and gross profit, examine customer discounts, compare a simulated budget with actual results, stress-test pricing assumptions, forecast a simple revenue trend, and generate an optional AI-powered executive narrative.

> **Data disclaimer:** All built-in data are generated by code. The 17 brands, 6,000 invoice records, allowed discounts, and budgets are fictional. This project does not contain any data from a real company, employer, or customer. Policy gaps and scenarios are **not** verified recoverable profits.

## What you can do

- **Executive dashboard:** Revenue, gross profit, weighted gross margin, weighted customer discounts, 17-brand analysis, segment profitability, regions, and monthly trends.
- **SQL-powered local database:** Deterministically create 6,000 fictional B2B invoices and a matching fictional budget table with SQLite indexes.
- **Pricing-policy gap analysis:** See which demo brands have the largest arithmetic gaps between actual discounts and hypothetical policy discounts.
- **Scenario simulation:** Choose how much to reduce above-policy discounts and change volume to examine hypothetical revenue/gross-profit effects and a break-even volume sensitivity.
- **Budget versus actual:** Compare synthetic planned revenue and gross profit with actual demo revenue; group correctly by brand, segment, and region.
- **Revenue trend:** An explicitly labeled 3-month linear trend baseline using up to the latest 6 filtered months.
- **Transactions and CSV exports:** Audit calculations row by row; download transactions, brand scorecards, and monthly figures.
- **Upload a CSV:** Test your own **authorized, non-confidential** transactions without writing them into the demo SQLite database. Budget figures are hidden for uploads.
- **AI analyst (optional):** Generate a concise executive brief with OpenAI using **only selected aggregate financial metrics**, not individual order rows. The analysis works without an API key using deterministic rules.
- **Quality checks:** A test suite and GitHub Actions CI validate core formulas, data generation, forecasts, uploads, and scenarios.

## Quick start

**Requirements:** Python 3.11+ and an internet connection for the initial package installation.

### macOS or Linux

```bash
cd margin-intelligence-dashboard
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

### Windows (PowerShell)

```powershell
cd margin-intelligence-dashboard
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

If PowerShell prevents activating the environment, you can use `.venv\Scripts\python.exe` instead of `python` in the install/run commands.

Streamlit usually opens at http://localhost:8501.

**No API key is required** for the dashboard, CSV upload, financial calculations, or rule-based insights.

### Optional: enable AI analysis

Set an OpenAI API key **only if you want to use the AI analyst tab**. Calls may incur charges.

- macOS/Linux for one terminal session: `export OPENAI_API_KEY="YOUR_KEY"`
- Windows PowerShell: `$env:OPENAI_API_KEY="YOUR_KEY"`
- Or locally copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and replace the placeholder with your key.

Never commit `.streamlit/secrets.toml` or put an API key directly in Python source. `.gitignore` excludes it. The optional model defaults to `gpt-4.1-mini`; the `OPENAI_MODEL` environment variable can override it. If a chosen model isn't available to your API account, choose an eligible model.

The AI feature sends **aggregated financial metrics, deterministic observations, and scenario deltas** to OpenAI, not customer/order-level data. Do not use confidential or personal data for hosted demos. Treat all generated commentary as a draft that must be checked against the underlying numbers.

## How finance calculations work

| Metric | Method |
|---|---|
| List revenue | Units × List price |
| Net revenue | List revenue × (1 − Actual discount) |
| COGS | Units × Unit cost |
| Gross profit | Revenue − COGS |
| Gross margin | Sum(Gross profit) ÷ Sum(Revenue) |
| Weighted average discount | 1 − Sum(Revenue) ÷ Sum(List revenue) |
| Over-policy price gap | List revenue × max(Actual discount − Allowed discount, 0) |
| Budget variance | Actual − Demo budget |

### Scenario sensitivity

For each order, the model reduces only the portion of its discount **above** the fictional policy threshold. A 50% correction to a 25% actual discount against a 15% policy would model a 20% discount, not a 12.5% discount.

For an additional volume-change assumption of -5%, the adjusted revenue and COGS totals both receive a 0.95 multiplier. Unit costs and list prices stay fixed. The break-even volume-loss measure answers: *What percentage of the modeled volume could disappear before the gross-profit improvement returns to its original level?* This measure is a mechanical sensitivity, **not a demand elasticity estimate**.

### Budget and forecast caveats

The fictional budget is generated from simulated realized activity and deterministic random differences. This is useful to show how an analyst builds an FP&A variance framework but is not an independent forecast or a historical corporate plan. The 3-month trend model fits a straight line to up to 6 observations and ignores seasonality, confidence intervals, and structural breaks.

### Accounting caveat

This educational app uses binary floating-point USD amounts and presents aggregated figures rounded for display. Production financial systems should specify currency precision, decimal rounding, reconciliation, controls, and audit requirements.

## Sample SQL exploration

```sql
SELECT brand,
       ROUND(SUM(revenue), 2) AS net_revenue,
       ROUND(SUM(gross_profit), 2) AS gross_profit,
       ROUND(100.0 * SUM(gross_profit) / NULLIF(SUM(revenue), 0), 2) AS gross_margin_pct,
       ROUND(SUM(policy_gap), 2) AS over_policy_price_gap
FROM transactions
GROUP BY brand
ORDER BY over_policy_price_gap DESC;
```

The SQLite file (`data/marginiq_demo.db`) is generated on first app launch. You can explore it with any compatible SQLite browser or the Python `sqlite3` library.

## Publishing to GitHub

1. Create a new **empty public** repository named `margin-intelligence-dashboard` (do not initialize it with a README; this package already contains one).
2. Open a terminal in the extracted project root.
3. Run:

```bash
git init -b main
git add .
git commit -m "Build MarginIQ finance analytics application"
git remote add origin https://github.com/YOUR_USERNAME/margin-intelligence-dashboard.git
git push -u origin main
```

Replace `YOUR_USERNAME` with your GitHub handle. GitHub Actions will then run tests on pushes.

## Deploying a live demo

You can publish a **fictional-data-only** demo on Streamlit Community Cloud:

1. Push the repository to GitHub.
2. Sign in to https://share.streamlit.io/ and choose **Create app**.
3. Select your GitHub repository, the `main` branch, and `app.py` as the entry point.
4. Deploy and copy the app URL into the top of this README.
5. Only add `OPENAI_API_KEY` to deployment secrets if you intentionally want to support paid AI requests. Avoid placing an unrestricted personal key in a public demo.

The app works fully in deterministic mode without API access, so leaving AI disabled on a publicly accessible app is a good default.

**FP&A and corporate finance:** Gross profit, gross margin, price realization, discount exceptions, budget variance, scenario analysis.

## Security and limitations

- Do not put proprietary employer data or customer records in public GitHub repositories.
- Uploaded CSV data are not deliberately persisted to SQLite, but a hosted Streamlit service still processes them in memory. Do not upload confidential data to public deployment.
- Do not commit secrets, database output, or personal files.
- This is not an audited accounting tool, investment advice, or a causal pricing optimization model.
